# Supabase

## Миграцияларды қолдану

Docker мен Supabase CLI орнатылмаған, сондықтан ең қарапайым жол —
SQL-ді браузерден орындау.

1. [supabase.com](https://supabase.com) сайтында жоба құрыңыз
2. **SQL Editor** бөлімін ашыңыз
3. Файлдарды **осы ретпен** орындаңыз:

```
0001_schema.sql     — кестелер, индекстер, триггерлер
0002_rls.sql        — RLS саясаттары
0003_progress.sql   — progress(), planned_progress(), pace(), әдет есептері
```

4. **Project Settings → API** бетінен `URL` мен `anon key` алыңыз
5. Жоба түбіндегі `.env.example` файлын `.env` деп көшіріп, толтырыңыз

CLI кейін орнатылса:

```
npx supabase link --project-ref <id>
npx supabase db push
```

## Схеманың екі маңызды ерекшелігі

**Бүкіл каскад бір кестеде.** `goals` — жыл да, кезең де, ай да, апта да,
күндік тапсырма да. Деңгей `level` бағанында, иерархия `parent_id` арқылы.
Күндік тапсырма — бөлек `tasks` кестесі емес, `level='day'` жолы.

**Әдеттер мүлде бөлек.** `habits` пен `habit_logs` `goals`-пен
байланыспайды және `progress()` оларға ЕШҚАШАН қарамайды. Бұл әдейі
жасалған: әдет — жететін нәтиже емес, күнделікті рефлекс.

## Функциялар

| Функция | Не істейді |
|---|---|
| `progress(goal_id)` | Нақты орындалу. Күндік тапсырма 100/0, ата-ана — балаларының `weight` бойынша орташасы. Рекурсивті. |
| `planned_progress(goal_id, on_date)` | «Керек еді» мәні. Кезеңдердің жинақталған салмағы бойынша. |
| `pace(goal_id, on_date)` | `progress − planned_progress`. Оң — алда, теріс — артта. |
| `goal_stats(goal_id, on_date)` | Үшеуін бір сұрауда. Клиент осыны шақырсын. |
| `habit_streak(habit_id)` | Үзіліссіз күн саны. Жоспарланбаған күндер серияны үзбейді. |
| `habit_consistency(habit_id)` | Соңғы 30 күндегі орындалу пайызы. |

### ⚠ `planned_progress` туралы

Ең жиі жіберілетін қате — «керек еді» мәнін өткен уақытпен есептеу:

```sql
-- ❌ БҰЛАЙ ЖАСАМАҢЫЗ
(current_date - period_start)::numeric / (period_end - period_start) * 100
```

Мысал (CLAUDE.md §5.2). Жүргізуші курсы 26.08 → 26.12. Кезеңдері:
курс 40% (26.08–07.11), дайындық 25% (09.11–22.11), тест 10% (24.11),
вождение 25% (25.11–22.12).

7 қарашада **уақыттың 60%-ы өтті**, бірақ жоспар бойынша **40%** болуы
керек — адам дәл кестемен келе жатыр. Сызықтық есеп «20% арттасың» деп
жалған дабыл берер еді.

Бұл ереже `lib/progress.test.ts` ішінде тестпен бекітілген. `npm test`
іске қосыңыз — бұзылса бірден көрінеді.
